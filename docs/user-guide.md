# 完整使用说明

## 1. 你需要准备什么

- 已安装并能正常使用的 Codex。
- 与电脑系统对应的**成品包**：Mac 为 `APINebula-macOS.zip`，Windows x64 为 `APINebula-Windows-x64.zip`。从 GitHub 下载的源码 ZIP 不等于成品包。
- 自己的 APINebula 图片模型分组 API Key、可用额度与网络。出图独立按 APINebula 计费，不包含在 Codex 订阅里。

成品包内已有运行环境和依赖，使用者不用安装 Python、运行 pip 或配置 S3。使用源码安装才需要自己准备 Python；见 [README](../README.md)。

## 2. 首次安装与配置

1. 把 ZIP **完整解压**到普通文件夹，不能在压缩软件预览里直接运行。
2. Mac 双击 `Install.command`；Windows 双击 `Install.cmd`，无需管理员权限。
3. 安装器先离线检查依赖和图片读写能力，再安装到个人目录：Mac 为 `~/.agents/skills/apinebula-imagegen`，Windows 为 `%USERPROFILE%\.agents\skills\apinebula-imagegen`。
4. 首次按提示粘贴自己的 Key 并回车。为保护密钥，输入时屏幕不显示字符。不要把 Key 发给聊天、同事或仓库。
5. 安装完成后回到 Codex，新建或继续聊天，输入“使用 $apinebula-imagegen 生成一张……”。若技能尚未显示，重新启动 Codex。

检测到已有 Key 时保留原配置；改 Key 时双击 `Configure-Key.command` / `Configure-Key.cmd`。安装器仅做安装和离线检查，不向服务商试图出图，也不验证额度。

如果系统提示首次打开确认，先确认文件来源和发布者提供的 SHA-256，再按系统正常流程确认。当前包没有开发者签名或 Apple 公证，不要求关闭安全保护。单位电脑有执行限制时交由管理员核实。

## 3. 四种使用方式

### 情况一：纯文生图

不需要提供图片或上传服务。在聊天里描述内容、风格、比例和其他要求：

> 使用 apinebula-imagegen 生成一枚圆形珐琅徽章，包含太阳、白鸽、彩虹和向日葵，金色描边，蓝色飘带不要文字，灰白背景。

可以指定横图、竖图、透明背景等视觉要求，但精确尺寸和实际格式由平台结果决定，不保证某个固定像素。默认模型标识为 `gpt-image-2.5`。

### 情况二：用户本地参考图 → 图生图

首次把本地 PNG/JPEG/WebP 附到聊天，同时写明要改哪里、保留什么：

> 去掉这张图蓝色飘带上的文字，保留金边、光泽和其他图案。允许将这张图临时上传到 tmpfiles.org 用于本次修图。

APINebula 的异步编辑接口需要可读取的网络链接。因此首次本地图需上传：

- 普通非敏感图片可用无需注册的 tmpfiles.org；约一小时自动到期，持有直链者可访问。技能会说明并获得对图片和服务的授权。一次授权只覆盖明确范围，不能视作对所有后续图片的授权。
- 不接受临时图床时，可自行配置私有 S3/R2；见[私有存储设置](../apinebula-imagegen/references/setup.md)。不要使用管理员存储密钥。

单张上限 20 MiB；超过时先另存较小副本。脚本随机化上传文件名，并核验直链内容与原文件字节一致，避免把展示页面交给编辑接口。上传失败时不会自动换网站。

### 情况三：用户复制网页图片链接 → 图生图

粘贴**图片直链**与需求：

> 参考这个图片链接，把背景改成纯白色，保留主体和材质：https://图片所在网站/实际原图地址

从网页复制图片时，选择“复制图片地址”，不要复制网页地址栏里的文章、分享页或相册网址。直链不一定以 `.png` / `.jpg` 结尾，但必须直接返回图片，并能被服务商读取。登录态、验证码、防盗链、一次性授权链接或已过期地址可能不可用。

有可用直链时直接交给 APINebula，不必先上传图床。不要把带有访问权限的私人图片链接公开分享。

### 情况四：生图后继续修改 → 图生图

在**同一聊天**里直接说：

> 把蓝色飘带改成深蓝色，其他保持一致。

无需重新复制图片，也无需再次提供链接或技能名。默认使用本聊天最近一张成功下载的出图。修改成功后，新图成为下一次修改的基础。

- 想从旧版本修改：“基于第一版，只把背景改白。”技能会使用对应任务状态，而不是要求再附图。
- 想重新从文字生成：“重新生成另一款徽章，不沿用上一张图。”
- 多个主题或候选图的指向不清时，会先确认，避免选错。
- 排队、失败或结果未知的任务不会替换上一张成功图。其他聊天的出图也不会混入当前聊天。

技能会查询父任务，直接复用其有效下载链接进行下一次编辑，通常无需重新上传。若平台已无法提供旧任务图片链接，再根据保留的本地副本处理；无法定位时会解释原因，不能保证永久恢复所有旧图。

## 4. 结果、版本与保存

出图时保存提示词、任务状态 `state.json` 和下载图片。修改使用新目录，保留旧版；不会默认覆盖产品资源。请保留任务与原图，日后续改需要用到它们。

当前图索引在本聊天工作目录的 `.apinebula/sessions/`，按 `CODEX_THREAD_ID` 隔离。迁移电脑、删除工作目录或在另一个运行环境打开聊天时，索引可能不可用；已知原任务路径可以用 `--from-state` 恢复。不要把密钥或任务签名链接提交到 Git。

没有线程环境变量的运行环境需要维护者为每个聊天指定独立 `--session-file`。普通 Codex 使用者无需手动传这些参数。

## 5. 等待、失败和收费

异步任务经历排队、处理中、完成或失败。技能每隔约 15–30 秒查询同一编号；完成后下载并实际检查图片。

- 网络中断或下载失败：保留编号，查询或下载同一个任务，不重新生成。
- 提交结果未知且没有编号：先查服务商任务/用量记录，不能通过删除目录或换目录盲目提交，以免重复计费。
- 平台报告失败：说明失败，不自动新建另一笔付费任务。
- 等待约 10 分钟仍未完成：保存状态供后续继续；不表示有后台程序永远轮询。

平台退款和收费以平台记录为准。安装和 `Check-Environment` 是离线检查，不会提交付费图像任务。

## 6. 更换密钥、升级、卸载

Key 保存在个人 `~/.config/codex-imagegen/apinebula-api-key`（Windows 对应用户目录）。POSIX 文件权限为 `0600`，Windows 使用用户 ACL；不是加密保险库，不要同步分享这个目录。

`APINEBULA_API_KEY` 环境变量优先于文件。改文件后仍用旧 Key 时检查是否设置过该变量；不要把完整变量值截图发出来。

成品包升级：解压新包再运行 Install。先检查新环境，再把旧技能备份到 `.agents/skill-backups/`，最后替换技能；升级不改外部 Key。确认新版本正常后，可自行移走不再需要的旧备份。源码安装器拒绝直接覆盖已有目录，应比较后手动升级。

卸载：关闭相关任务后移走个人 `.agents/skills/apinebula-imagegen`，需要时另行清理备份和密钥配置。只删技能不会删除外部密钥和之前保存的输出。

## 7. 常见问题

| 问题 | 如何处理 |
|---|---|
| 提示找不到 Python 或 `.venv` | 先确认拿的是成品包并运行过 Install。成品包用自己的 `run.command` / `run.cmd`；源码包需要装依赖。 |
| Codex 没发现技能 | 确认 `SKILL.md` 位于个人 `.agents/skills/apinebula-imagegen/`，再重启 Codex。 |
| 401/403 | 核对 APINebula 图片分组权限和 Key；双击 Configure-Key 更新，检查环境变量是否覆盖。 |
| 余额不足或模型不可用 | 到 APINebula 后台核实额度和模型分组，不换其他模型冒充成功。 |
| 本地图不能上传 | 核对服务授权、格式、20 MiB 上限和网络；临时图床有可用性限制，保留原图。 |
| 网页链接无法编辑 | 确认是直链，排除登录、防盗链和过期；必要时取得本地原图后再授权上传。 |
| “继续修改”找不到上一张图 | 留在原聊天并保留原工作目录；提供已知任务版本，不能用其他聊天最近图片替代。 |
| TLS 或代理连接失败 | 检查本机/单位代理和证书；不关闭 TLS 校验。经诊断可用单次 `--direct`，不改全局设置。 |
| 安装检查通过但出图失败 | 检查只验证本地依赖；服务商 Key、额度与网络仍可能有问题。 |

详细参数见[命令行参考](cli.md)，实际已验证和未验证的边界见[验证记录](../验证记录.md)。
